# internal/entity 21.05.2026

1. Суть пакета model (Классический/MVC подход)
Слово Model (Модель) пришло к нам из паттерна MVC, который долгие годы правил веб-разработкой (Django, Ruby on Rails, Laravel).
Что это такое: В этом подходе модель — это прямое отражение таблицы в базе данных. 
Если в SQL есть таблица links с полями id, original_url, created_at, то в Go создается type Link struct точно с такими же полями и ORM-тегами (например, db:"id" или gorm:"primaryKey").
Главный минус в Go: Модели намертво связывают ваш код с конкретной базой данных. Если вы захотите поменять PostgreSQL на MongoDB, вам придется менять структуры по всему проекту, потому что теги баз данных «намертво» вшиты в эти модели.
2. Суть пакета entity (Подход Clean Architecture / DDD) Слово Entity (Сущность) используется в Чистой Архитектуре Роберта Мартина.
Что это такое: Это чистый бизнес-объект, который живет по правилам реального мира, а не по правилам баз данных. Пакету entity абсолютно всё равно, где будут храниться данные — в Postgres, Redis, файле или оперативной памяти.
Главная особенность: Внутри структур из пакета entity нет никаких тегов баз данных (вроде gorm:"..." или bson:"..."). 
Там могут быть только теги для JSON, если сущность отдается наружу, но в строгой архитектуре нет даже их.

А где же тогда пишутся SQL-теги в чистой архитектуре? Они пишутся на уровне слоя repo (инфраструктуры). 
Внутри internal/repo/postgres/ создается своя локальная структура (например, type linkRow struct), которая умеет сохранять себя в базу, а затем конвертируется в чистый entity.Link.

Что выбрать для этого проекта? Поскольку мы твердо решили строить расширяемую систему с заделом на разные базы данных и транспорты, 
пакет entity — единственный правильный выбор. 
Это защитит ядро нашего сократителя ссылок от влияния внешних технологий.
